# Release v1.6.1

## 概述

本版本根据两份外部代码审查（review_by_kimi.md、review_by_deepwiki.md）的 A 类建议，完成了三项安全与工程质量的实质性修复。所有审查文档已归档至 `docs/archive/`。

---

## 变更详情

### 安全：PIN 明文存储 → bcrypt 哈希

**根因**：`config.json` 中 `security.pin` 以明文存储，配置文件泄露即暴露访问凭证。

**方案**：引入 `security.pinHash` 字段存储 bcrypt 哈希，`security.pin` 仅作为前端传入的临时字段，在保存前自动哈希并清空。

- **`internal/config/config.go`**：
  - `SecurityConfig` 新增 `PINHash string` 字段。
  - 新增 `SanitizeSecurity(cfg *Config)`：若 `PIN` 非空，用 `bcrypt.GenerateFromPassword` 生成哈希存入 `PINHash`，并清空 `PIN`。
- **`internal/handler/auth.go`**：
  - `HandlePIN` 验证改为 `bcrypt.CompareHashAndPassword`。
  - 删除已弃用的 `constantTimeCompare` 函数。
- **`internal/server/server.go`** / **`internal/service/config.go`**：
  - `UpdateConfig` 和 `checkAndReloadConfig` 中调用 `SanitizeSecurity`，确保热重载后新 PIN 也能自动哈希。
- **`cmd/msp/main.go`**：
  - 启动时自动迁移：若检测到旧版明文 `PIN`，自动哈希并保存回 `config.json`。
- **`config.example.json`**：`"pin": "0000"` 改为 `"pinHash": ""`。

### 安全：RateLimiter / PIN 暴力破解防护的内存上限

**根因**：`RateLimiter.buckets` 和 `pinAttempts` 两个 map 均只增不减，在公网可达场景（Cloudflare Tunnel）下可被 IP 轮换攻击耗尽内存。

**方案**：
- **`internal/handler/middleware.go`**：`RateLimiter` 新增 `maxSize = 10000`，超出后对新 IP 执行随机驱逐。
- **`internal/handler/auth.go`**：`pinAttempts` 新增 `maxPinAttempts = 1000`，超出后随机驱逐旧条目。

### 工程：消除 sqlite.go DRY 违反

**根因**：14 个数据库方法重复粘贴同一套 `if s.db == nil { log.Printf(...); return nil }` 守卫逻辑。

**方案**：
- **`internal/storage/sqlite.go`**：提取 `guard(name string)` 和 `guardTx(tx, name string)` 两个内部 wrapper，替换全部 14 处重复代码。

### 可观测性：高危数据库操作增加日志

- **`internal/storage/sqlite.go`**：`DeleteByShareRootsNotIn` 在 `shareRoots` 为空（执行全表删除）时输出 `[WARN]` 日志，提高操作可观测性。

## 兼容性

- **向后兼容**：首次启动自动将旧版明文 `PIN` 迁移为 `PINHash`，无需手动干预。
- **配置**：`security.pin` 字段仍可写入，系统会自动哈希为 `security.pinHash`。
- **API**：无 API 接口变更。
