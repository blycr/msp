## v1.12.3

本轮没有用户可见的功能或行为变化，交付的是**工具链与依赖收口**：安全更新 + 依赖自动更新全部打通。

### 安全 / 工具链

- **`go.mod` 的 `go` 指令 `1.25.0` → `1.26.0`**：从源码构建现在需要 Go 1.26+（此前用 1.25 自行构建亦可）。发布二进制由 `release.yml` 按 `go.mod` 自动选取 Go 1.26.x 构建
- **`golang.org/x/text` `0.37.0` → `0.42.0`**：跨过 GO-2026-5970 等修复（该依赖经 `gorm/schema` 进入媒体与数据库路径）
- **`golang.org/x/crypto` `0.51.0` → `0.57.0`**、**`golang.org/x/sys` `0.44.0` → `0.48.0`**
- `github.com/stretchr/testify` `1.11.1` → `1.12.1`、`gorm.io/gorm` `1.31.1` → `1.31.2`、`gopkg.in/yaml.v3` → `go.yaml.in/yaml/v3` `3.0.5`

### 前端依赖

- `vite` `8.0.12` → `8.3.4`
- `vite-plugin-pwa` `1.3.0` → **`2.0.0`**（大版本）。这不是盲升：已在隔离 worktree 中构建并逐项比对生成的 Service Worker —— 与升级前**语义完全一致**（`skipWaiting`、`clientsClaim`、`/api/` navigate denylist、`/api/` `NetworkOnly` 运行时缓存、9 项 precache），仅内容 hash 变化。PWA 离线行为不受影响

### Docker

- 后端构建基镜像 `golang:1.25-alpine` → **`golang:1.26-alpine`**：与 `go.mod` 的 `go 1.26.0` 对齐，避免构建阶段让 Go 自行下载 toolchain
- 运行基镜像 `alpine:3.21` → `alpine:3.24`

### CI / 依赖自动化

- `actions/setup-go` v5 → **v7**（v7.0.0 仅迁移到 ESM 并升级 `@actions/cache`，无输入或行为变更）
- **修复前端依赖长期收不到更新 PR 的问题**：Dependabot 配置写的是 `npm` 生态，而 `web/` 由 Bun 管理（只跟踪 `bun.lock`，没有 `package-lock.json` / `yarn.lock` / `pnpm-lock.yaml`），`npm_and_yarn` 更新器直接以 `misconfigured_tooling` 中止。改为 `package-ecosystem: "bun"` 后立即产出更新 PR
- 至此四类依赖（Go / Bun / GitHub Actions / Docker 基础镜像）的自动更新全部可用

### 升级说明

配置、数据库与 API 均无变化，无需迁移。用 Docker 部署的用户直接拉新镜像即可。

需要注意的是：**从源码构建的最低 Go 版本提高到 1.26**。只使用发布二进制的用户不受影响。
