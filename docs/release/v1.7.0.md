# Release v1.7.0

## 概述

本版本围绕播放器体验、日志系统和 UI 交互进行三项核心重构：移除"继续观看"列表并重新设计恢复播放行为；引入 Warning 日志级别与双通道输出机制；全面升级设置对话框的视觉层级与交互一致性。

---

## 变更详情

### 恢复播放行为重新设计

**动机**：
原有"继续观看"（Continue Watching）列表在侧边栏占据固定空间，与搜索模式存在视觉竞争，且实现复杂度较高。简化后的恢复播放行为更直接、更符合用户预期。

**实现**：
- 后端：移除 `RecentProgress` 领域类型及相关 `ListRecentProgress` 方法
- 后端：移除 `GET /api/progress/recent` 端点
- 前端：移除侧边栏"继续观看"区域及相关状态（`recentProgress` 等）
- 前端：点击媒体项时仍自动恢复上次播放进度，行为不变
- 前端：搜索模式下界面更简洁，无额外区域需要隐藏

### 日志系统重新设计

**动机**：原日志系统仅支持 Info/Error 两级，无法区分警告与一般信息。同时日志仅输出到文件，调试时需要 tail 文件，不够便捷。

**实现**：
- 后端：新增 `Warning` 日志级别，位于 Info 与 Error 之间
- 后端：日志同时输出到文件和控制台（dual output），开发调试更直观
- 后端：`internal/service/logger.go` 重构，支持级别过滤与多输出目标
- 前端：同步更新日志上报级别白名单

### 设置对话框视觉层级优化

**动机**：设置对话框的选项平铺展示，缺乏视觉分组，用户在查找特定设置时认知负担较高。

**实现**：
- 前端：重新设计 `settings.js` 对话框布局，引入分组标题与分隔线
- 前端：相关设置项按功能聚类（播放/网络/安全/外观），提升扫描效率
- 前端：优化表单控件的对齐与间距，统一 36px 按钮高度规范
- 样式：`dialog.css` 与 `form.css` 配合调整，支持分组标题的 Neo-Industrial 风格

### 其他改进

- **前端**：修复音视频进度条与音量条的鼠标指针样式及拖拽时文字选中问题
- **测试**：`TestMediaServiceGetOrBuildMediaCache` 增加后台任务等待，消除测试清理阶段的竞态错误
- **工程**：禁用 Git `autocrlf`，消除 Windows 开发环境的 LF/CRLF 警告

## 兼容性

- **API 移除**：`GET /api/progress/recent` 端点已移除。若存在外部调用方需适配。
- **配置**：无变更，`config.json` 自动兼容。
- **数据库**：`favorites` 与 `playback_progresses` 表保留，无迁移需求。

## 影响评估

- **体验**：设置对话框信息架构更清晰；恢复播放行为更直接
- **性能**：移除"继续观看"列表减少启动时一次 API 请求和前端 join 计算
- **资源占用**：无显著变化
