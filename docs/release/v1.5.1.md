# Release v1.5.1

## 概述

本版本是 v1.5.0 的紧急热修复，修复了安全 release 引入的 4 个影响正常使用的 regression 和 1 个潜在崩溃问题。所有修复均保持向后兼容，无破坏性变更。

## 变更详情

### 修复：添加共享目录后前端不显示媒体

**根因**：多个 bug 叠加导致——DB 扫描时旧数据未清理触发唯一约束冲突、`LoadMediaResponseFromDBScan` 返回空 share 对象、前端缺少刷新后自动轮询机制。

- **`internal/media/store.go`**
  - `LoadMediaResponseFromDBScan` 添加 `copy(resp.Shares, shares)`，修复返回 `[{"label":"","path":""}]` 的问题。
  - `IndexMediaToDB` 中先执行 `cleanupStaleData` 再执行 `performScan`，避免事务内旧数据与新数据产生 `UNIQUE constraint failed: media_items.path` 冲突。
  - `performScan` 的 batch 内增加 `batchPaths` 去重，防止同一路径重复插入。
- **`internal/storage/sqlite.go`**
  - `UpsertMediaItems` 的 `OnConflict` 从 `id` 列改为 `path` 列。由于 v1.5.0 引入的 AES-GCM 随机 nonce 导致每次扫描生成不同 `id`，基于 `id` 的 upsert 无法匹配旧记录。
- **`web/src/modules/ui/render.js`**
  - `renderList()` 的空状态判断从仅检查 `shares` 改为检查 `videos/audios/images/others` 是否有实际内容，更健壮。
- **`web/src/modules/actions.js`**
  - `loadMedia(true)` 成功后若服务器返回 `scanning: true`，自动启动 `startMediaPolling()` 轮询（1.5s 间隔，最多 15 次），无需手动刷新页面即可看到扫描结果。

### 修复：控制台出现大量无格式日志

**根因**：`LoggerService.Log()` 手动拼接时间戳后，又通过 `log.Println()` 输出；而 `SetupLogger()` 设置了 `log.LstdFlags | log.Lmicroseconds`，导致标准库再追加一次时间戳，产生双重时间戳。

- **`internal/service/logger.go`**
  - 移除手动时间戳拼接，仅保留标准库格式化的单条时间戳。

### 修复：Local 用户触发 429 Too Many Requests

**根因**：`HandleMedia` 的 `refreshCooldown = 30s` 和 `WithRateLimit` 的 token-bucket 限流对所有访问级别生效，包括 Local 和 LAN。

- **`internal/handler/media.go`**
  - `refreshCooldown` 仅对非 Local 访问生效。
- **`internal/handler/middleware.go`**
  - `WithRateLimit` 对 `LAN` 访问也豁免限流。
  - `getRateLimitConfig` 大幅收紧限流范围：仅对 4 个真正的管理/敏感端点限流（`POST /api/pin`、`GET /api/media?refresh=1`、`POST /api/config`、`POST /api/shares`），其余所有 API（stream、probe、progress、subtitle、log 等）完全不限流。

### 修复：播放时 `TypeError: Cannot read properties of null (reading 'play')`

**根因**：`playItem` 注册 Plyr `ready` 回调后，回调内部有 `await getProgress()` 异步等待；若用户在等待期间切换媒体，`destroyPlyr()` 会将 `state.plyr` 置为 `null`，回调执行时调用 `state.plyr.play()` 崩溃。

- **`web/src/modules/player/play.js`**
  - 音频/视频 `ready` 回调和视频切换 `setTimeout` 中的 `state.plyr.play()` 均添加 `if (state.plyr)` 守卫。
- **`web/src/modules/player/core.js`**
  - source 切换 `ready` 回调中的 `state.plyr.play()` 同样添加 null 检查。

## 影响评估

- **安全性**：限流策略收紧后，管理端点防护力度不变；媒体流端点不再限流，但 LAN/Local 已豁免，Remote 正常播放也不受影响。
- **兼容性**：完全向后兼容，无配置迁移需求。
- **性能**：无变化。
