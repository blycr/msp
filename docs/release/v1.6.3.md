# Release v1.6.3

## 概述

本版本是 MSP 从"文件列表"向"现代媒体库体验"演进的关键 release。围绕家庭场景下大库存储、跨会话续播和视觉浏览三大痛点，一次性交付了继续观看、文件夹层级浏览、收藏标记、视频缩略图和转码状态反馈五项功能。所有改动均保持向后兼容，旧数据库通过 GORM `AutoMigrate` 自动完成表结构升级，无需手动干预。

---

## 变更详情

### 继续观看（Continue Watching）

**动机**：v1.6.0 的确定性 MediaID 为跨设备进度续播扫清了障碍，但用户仍需手动在文件列表中定位上次观看的内容。本特性将播放进度提升为首页核心入口。

**实现**：

- **后端**：
  - `internal/domain/progress.go`：新增 `RecentProgress` 领域类型，承载 `media_id`、`position`、`duration` 及 `updated_at`。
  - `internal/storage/sqlite.go`：`ProgressStore` 接口新增 `ListRecentProgress(limit int)` 方法；SQLite 实现通过 `ORDER BY updated_at DESC` 分页查询 `playback_progresses` 表。
  - `internal/handler/progress.go`：新增 `GET /api/progress/recent?limit=N` 端点，默认上限 10 条，返回结果按更新时间降序排列。

- **前端**：
  - `web/src/modules/progress.js`：应用启动时自动调用 `/api/progress/recent?limit=5`，将返回的 `media_id` 与当前内存媒体库做 join 映射，生成带封面/标题的续播卡片。
  - `web/src/modules/ui/render.js`：侧边栏顶部新增"Continue Watching"区域；搜索模式下自动隐藏，避免与搜索结果竞争视觉焦点。
  - 点击续播条目直接调用 `playItem()` 并传入恢复进度，无需二次确认。

### 文件夹层级浏览（Folder Browse）

**动机**：当共享目录包含 500+ 文件（如电视剧分季分集存放）时，扁平列表的浏览效率极低。本特性在保留原有扁平模式的前提下，新增目录树浏览能力。

**实现**：

- **后端**：
  - `internal/domain/media.go`：`MediaItem` 新增 `RelPath` 字段，存储相对于 share root 的目录路径（含子目录）。
  - `internal/scanner/scanner.go`：`buildMediaItem` 在扫描阶段通过 `filepath.Rel(shareRoot, filePath)` 计算 `RelPath`，入库时随其他字段一并写入。

- **前端**：
  - `web/src/modules/folder.js`：从扁平 `mediaItems` 列表实时提取目录树结构（`shareLabel + '/' + relPath` 前缀分组），支持无限层级嵌套。
  - `web/src/modules/ui/render.js`：支持 `flat` / `folder` 双模式渲染；文件夹模式下显示面包屑导航（`ShareLabel > Season 1 > ...`）、子文件夹列表和当前目录文件。
  - 侧边栏增加 Folder / Flat 模式切换按钮，状态持久化到 `state.browseMode` 和 `state.currentFolder`。

### 收藏 / 标记（Favorites）

**动机**：用户在浏览过程中需要一种轻量方式标记"想稍后观看"的内容，而不依赖外部笔记或浏览器书签。

**实现**：

- **后端**：
  - `internal/domain/favorite.go`：新增 `Favorite` 领域类型（`media_id`、`created_at`）和 `FavoriteStore` 接口（`List` / `Add` / `Remove` / `Is`）。
  - `internal/storage/sqlite.go`：SQLite / `Store` 实现收藏 CRUD；`AutoMigrate` 自动创建 `favorites` 表。
  - `internal/handler/favorite.go`：新增 `/api/favorites` REST 端点。
    - `GET`：返回当前全部收藏 ID 列表。
    - `POST`：添加收藏（幂等，重复添加返回 200）。
    - `DELETE`：移除收藏。

- **前端**：
  - `web/src/modules/favorite.js`：启动时批量拉取收藏状态到 `Set<string> favoriteIds`，后续操作本地即时更新并后台同步，避免每次交互都请求后端。
  - `web/src/modules/ui/render.js`：每个文件列表项右侧渲染星标按钮（☆/★），点击即时切换并触发后端同步。
  - 导航 Tab 栏新增第五个 `Favorites` Tab，跨视频/音频/图片类型聚合显示所有已收藏媒体；内部支持搜索、排序和分页。
  - 收藏 Tab 下自动隐藏"继续观看"和文件夹浏览控件，保持界面聚焦。

### 视频缩略图（Video Thumbnails）

**动机**：纯文本文件名在视频浏览场景下信息密度过低，用户需要视觉线索快速识别内容。

**实现**：

- **后端**：
  - `internal/handler/thumbnail.go`：新增 `GET /api/thumbnail?id=xxx` 端点。
    - 调用 `DecodeID` 还原路径，验证文件存在且为视频类型。
    - 通过 `exec.Command` 调用 ffmpeg 截取第 5 秒画面（`-ss 00:00:05 -vframes 1`），输出为 JPEG。
    - 缩略图缓存到 `<exe_dir>/thumbs/<media_id>.jpg`，带 `If-Modified-Since` 和 24h HTTP 缓存头。
    - 信号量（`semaphore.NewWeighted(2)`）限制最多 2 个并发 ffmpeg 缩略图生成任务，避免扫描或批量浏览时触发 ffmpeg 进程风暴。
    - 若 ffmpeg 不可用或截图失败，返回 404，前端优雅降级为默认图标。

- **前端**：
  - `web/src/modules/ui/render.js`：视频列表项左侧渲染 `<img>` 缩略图，使用 `loading="lazy"` 延迟加载，减少首屏带宽和 ffmpeg 触发次数。

### 转码进度反馈（Transcode Status）

**动机**：当视频需要实时转码时，用户面对的是一个空白或静止的播放器，无法区分"网络慢"和"正在转码"。本特性消除这一不确定性。

**实现**：

- **前端**：
  - `web/src/modules/player/play.js`：播放视频/音频时，若 `getPlaybackUrl()` 返回的 `mode` 为 `transcode`，在播放器上方显示浮动状态条。
  - 状态机分为两个阶段：
    1. "检测兼容性..."（probe 阶段，后端决策中）
    2. "正在转码，请稍候..."（转码进程已启动，带旋转 CSS 动画）
  - `web/src/modules/player/core.js`：媒体元素触发 `canplay` 事件后，状态条自动淡出消失。

## 兼容性

- **向后兼容**：旧数据库通过 GORM `AutoMigrate` 自动添加 `favorites` 表和 `media_items.rel_path` 列，无需手动迁移。
- **文件夹浏览**：已有媒体库中的旧记录需重新扫描（或等待自动后台扫描）才能填充 `rel_path` 字段，在此之前文件夹浏览功能对新扫描的文件正常工作。
- **API**：新增端点均为增量接口，不影响现有客户端行为。
- **配置**：无配置格式变更；`thumbs/` 目录首次请求时自动创建。

## 影响评估

- **体验**：大库浏览效率显著提升——目录树将 500+ 扁平条目组织为可折叠的层级结构；缩略图使视觉识别速度从"阅读文件名"提升到"图像记忆"级别。
- **性能**：缩略图生成受信号量严格限制，最坏情况下仅 2 个 ffmpeg 并发；缩略图缓存为纯磁盘文件，零数据库开销；懒加载确保只有视口内视频触发后端请求。
- **资源占用**：`thumbs/` 目录按每张 JPEG 约 20-50 KB 估算，1000 部影片约占用 20-50 MB 磁盘空间，可安全忽略。
