# Release v1.6.0

## 概述

本版本根治了 v1.5.0 引入的 AES-GCM 随机 nonce 导致的 MediaID 不稳定问题，彻底消除了项目中最后一个包级全局变量，并带来了多项可观测性和兼容性改进。

**关键升级提示**：首次启动时会自动迁移 `PlaybackProgress` 表中的旧格式 `media_id` 到新的确定性 ID，无需手动操作。

---

## 变更详情

### 修复：确定性 MediaID（根治 v1.5.1 临时补丁）

**根因**：v1.5.0 引入 AES-GCM 加密生成媒体 ID，但使用随机 nonce，导致同一文件每次扫描产生不同 ID。v1.5.1 的临时补丁将 `UpsertMediaItems` 的 `OnConflict` 从 `id` 改为 `path`，造成旧书签失效、孤儿记录、不必要的 UPDATE。

**方案**：保持 AES-GCM 加密可逆性不变，将随机 nonce 改为通过 `HMAC-SHA256(key, path)[:gcm.NonceSize()]` 确定性派生。同一文件路径 + 同一密钥 → 始终产生相同 ID。

- **`internal/util/crypto_id.go`**
  - 删除 `globalIDKey` 包级全局变量和 `SetIDKey` 函数。
  - 新增 `IDCodec` 结构体，包含 `EncodeID` / `DecodeID` 方法。
  - `EncodeID` 使用 HMAC-SHA256 派生确定性 nonce。
- **`internal/storage/sqlite.go`**
  - `UpsertMediaItems` 的 `OnConflict` 从 `"path"` 改回 `"id"`，恢复标准主键冲突策略。
- **`cmd/msp/main.go`**
  - 启动时自动执行一次性迁移：`PlaybackProgress` 旧 `media_id` → `DecodeID` 还原路径 → 新确定性 `EncodeID(path)` → 更新记录。
  - 迁移失败仅记录日志，不中断启动。

### 架构：全面依赖注入化

项目中最后一个包级全局变量 `globalIDKey` 已消除，`IDCodec` 实例从 `main.go` 创建后注入到所有依赖组件。

- **`internal/media/processor.go`**：`NewMediaProcessor` 接收 `idCodec` 参数；新增 `IDCodec()` 访问方法。
- **`internal/scanner/scanner.go`**：`WalkShares` 和 `shareWalker` 接收 `idCodec`；`buildMediaItem` 改为 `shareWalker` 方法。
- **`internal/scanner/subtitle.go`**：`FindSidecarSubtitlesCached` / `FindSidecarSubtitles` / `collectSubtitles` 接收 `idCodec`。
- **`internal/media/media.go`**：`BuildMediaResponse` 接收 `idCodec` 参数。
- **`internal/cache/media.go`**：`buildAndUpdate` 通过 `processor.IDCodec()` 传递。
- **`internal/handler/handler.go`**：`Deps` 和 `Handler` 增加 `IDCodec` 字段。
- **`internal/handler/stream.go`**：`DecodeID` 调用从 `util.DecodeID` 改为 `h.idCodec.DecodeID`。

### 文档修复

- **`README.md`**：删除 Acknowledgements 中已移除的 Gin 框架引用（项目已完全使用 `net/http` 标准库）。
- **`README.md`**：更新 Firefox 已知问题说明——代码已做 GPU 层兼容性处理（`translateZ(0)`），不再无条件推荐换用 Chrome。

### CI / 覆盖率

- **`.github/workflows/check.yml`**：`go test` 增加 `-coverprofile=coverage.out`。
- **`.github/workflows/check.yml`**：新增 `actions/upload-artifact@v4` 步骤上传 coverage 报告。
- **`README.md`**：增加 Codecov coverage badge。

### 可观测性

- **`internal/storage/sqlite.go`**：12 个数据库操作函数在 `s.db == nil` 的静默返回处增加 `[WARN]` 日志，包括 `GetProgress`、`SetProgress`、`GetAllPrefs`、`SetPrefs`、`GetScanMeta`、`SetScanMeta`、`UpsertMediaItem`、`UpsertMediaItems`、`DeleteStaleByScan`、`DeleteByShareRootsNotIn`、`QueryMediaItems`、`CountMediaItems`。

### 测试

- **新增 `internal/handler/integration_test.go`**：
  - `TestScanThenList`：扫描共享目录 → `BuildMediaResponse` 返回正确条目。
  - `TestMediaIDStability`：同一文件多次扫描 ID 不变。
  - `TestMediaIDStabilityViaScanner`：通过 `BuildMediaResponse` 验证确定性。
  - `TestHandleMediaIntegration`：`/api/media` 返回正确 JSON。
  - `TestStreamRange`：Range 请求返回 `206 Partial Content`。
  - `TestSubtitleIntegration`：字幕检测与 ID 生成集成验证。

### 配置验证

- **`internal/config/validate.go`**：
  - `isValidIP` 从仅支持 IPv4 的自定义解析改为 `net.ParseIP`，支持 IPv6 地址（如 `::1`）。
  - `isValidIPOrCIDR` 的 CIDR 验证从自定义前缀长度检查改为 `net.ParseCIDR`，支持 IPv6 CIDR（如 `::1/128`）。

### 代码清理

- **`internal/cache/media.go`**：`LoadFromDisk` 中 `already || !need` 恒等于 `already`，删除冗余的 `need` 变量计算。

## 兼容性

- **向后兼容**：旧 AES-GCM ID（随机 nonce 生成）仍可被 `DecodeID` 解密，因为加密算法本身未改变。
- **数据库**：首次启动自动迁移 `PlaybackProgress` 的 `media_id`，无需手动干预。
- **配置**：无配置格式变更。
- **API**：无 API 接口变更。
