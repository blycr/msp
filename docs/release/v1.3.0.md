# Release v1.3.0

## 概述

本版本是后端架构层面的重大重构：将 `internal/media/` 包中所有包级全局变量收敛到 `MediaProcessor` 结构体中，彻底消除隐藏依赖关系，提升可测试性和并发安全性。

## 变更详情

### 架构重构

- **新增 `internal/media/processor.go`**：引入 `MediaProcessor` 结构体，统一持有以下原先分散在四个文件中的全局状态：
  - `mediaDB`（SQLite 连接，原 `store.go`）
  - `probeCache` + `cacheTTL`（ffprobe 结果缓存，原 `probe.go`）
  - `ffmpegPath` / `ffprobePath` + `pathOnce`（路径发现，原 `probe.go`）
  - `transcodeLimit` + `activeProcesses`（并发限制与进程跟踪，原 `transcoder.go`）
  - `hwOnce` + `hwResult` + `hwDisabled`（硬件加速检测，原 `hwaccel.go`）
- **构造函数 `NewMediaProcessor(db, opts...)`**：采用 Option 模式，支持 `WithTranscodeLimit(n)` 自定义并发上限，默认限制为 2。
- **线程安全改进**：
  - `cacheTTL` 从裸 `time.Duration` 改为 `atomic.Int64`（纳秒），消除跨 goroutine 读写竞争。
  - `hwDisabled` 从 `sync.RWMutex` 保护的 `bool` 改为 `atomic.Bool`。
  - 每个 `MediaProcessor` 实例拥有独立的 `sync.Once`，天然支持并行测试而不互相污染。

### 文件级迁移

| 文件 | 主要变更 |
|------|---------|
| `store.go` | 删除 `mediaDB` / `SetDB()`；`LoadMediaFromDB`、`ReindexAndLoadMedia`、`IndexMediaToDB`、`LoadMediaResponseFromDBScan` 等改为 `MediaProcessor` 方法 |
| `probe.go` | 删除全局缓存与路径变量；`FFmpegPath`、`CheckFFmpeg`、`GetCodecInfo` 等改为方法；`ResetPathsForTest()` 删除（不再需要） |
| `transcoder.go` | 删除全局 channel / map；`TranscodeStream`、`KillAllTranscodeProcesses` 改为方法；`limitReleaser` 改为持有 limit channel 引用而非全局变量 |
| `hwaccel.go` | 删除全局 `sync.Once` / `sync.RWMutex`；`DetectHWAccel`、`BuildVideoArgs`、`FormatHWAccelStatus` 等改为方法；`ResetHWAccelForTest()` 删除 |
| `media.go` | 提取 `newMediaResponse(shares)` 公共构造函数，消除 `BuildMediaResponse` 与 `LoadMediaResponseFromDBScan` 之间的重复构造逻辑 |

### 调用方更新

- `cmd/msp/main.go`：提前初始化数据库 → 创建 `MediaProcessor` → 注入 `server.New` → `handler.New`。
- `internal/server/server.go`：`New` 签名改为 `New(cfgPath, processor)`。
- `internal/handler/handler.go`：`Deps` 和 `Handler` 新增 `Processor *media.MediaProcessor` 字段。
- `internal/cache/media.go`：`NewMediaCache` 签名改为 `NewMediaCache(processor, cacheFilePath, ttl)`。
- `internal/service/config.go`：`ConfigService` 新增 `processor` 字段；`GetConfigView` 中的 FFmpeg 可用性查询改为通过 `processor` 方法。

### 测试

- 所有 `internal/media/*_test.go` 改为通过 `NewMediaProcessor(nil/sq)` 创建实例，不再依赖全局状态。
- `internal/cache/*_test.go`、`internal/handler/*_test.go`、`internal/server/*_test.go`、`internal/service/*_test.go` 更新构造签名以匹配新接口。
- 为 `IsDBAvailable`、`CheckFFmpeg`、`CheckFFprobe`、`FFmpegAvailable` 添加 nil-receiver 安全保护，方便测试场景传入 nil processor。
- 修复 `stream_test.go` 中两个 pre-existing 的 `gosec G306` 警告（文件权限 `0640` → `0600`）。

## 影响评估

- **可测试性**：media 包函数不再依赖隐藏的全局状态，单元测试可以并行运行而不会互相干扰。
- **并发安全**：`cacheTTL` 和 `hwDisabled` 改用原子操作，消除数据竞争隐患。
- **可维护性**：所有媒体相关依赖通过构造函数显式注入，新增功能（如多实例、mock 替换）更容易实现。
- **行为兼容性**：对外功能（转码、探针、硬件加速检测）逻辑完全保持不变，仅内部实现从包函数改为实例方法。
