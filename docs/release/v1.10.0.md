## v1.10.0

### 修复

- **配置热重载静默失效**：`LogFile` 变更不重开日志文件、`Shares` 变更缓存不刷新、`Port`/编码参数变更无任何提示——统一改为 diff-apply：日志文件原子重开（失败保留旧 fd）、Shares 变更触发后台重建、不可热更字段明确 WARN"需重启生效"
- **后台扫描被客户端断开杀死**：首次全量扫描此前绑定请求 ctx，客户端断开即作废重扫；现构建统一在服务级 context 上执行，请求只约束等待时长
- **退出时缓存写入截断**：优雅关闭顺序调整为 停转码 → HTTP 排空 → 取消后台任务 → 等待收尾（5s 兜底）→ 关库关日志，消除 `.tmp` 残留
- **DB 不可用静默降级**：进度/收藏/偏好此前返回空数据冒充成功；现返回 503 `{"error":"db_unavailable"}`，启动失败有醒目横幅，前端置灰收藏并静默跳过进度保存

### 改进

- **日志收敛到 `log/slog`**：stdlib log / LoggerService / stderr 三轨统一，40 处调用同一 handler；异步缓冲、级别、轮转、新设备检测语义不变
- **新增 `/healthz`**：`{status, db, uptime}`，豁免 PIN（保留 IP 白名单与限流）
- **前端渲染模型**：列表/播放列表改 keyed diff + 事件委托，翻页/切 tab/搜索/收藏不再全量重建 DOM；pager 稳定化；缩略图重试定时器集中管理并随行移除清理

### 说明

- `Playback.Video.Encoding`（HWAccel/MaxJobs）与 `Port` 声明为不可热更字段，变更时日志告警需重启；做成可热更需重写转码信号量与 HW 检测，本次未纳入
- 媒体索引路径在 DB 不可用时维持内存降级（功能正常），不受影响
