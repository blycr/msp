# Release v1.2.2

## 概述

本版本聚焦代码质量修复：消除前端播放器内存泄漏、修复后端两个静默失效问题（缓存吞错、日志轮转失败）、补充核心单元测试。

## 变更详情

### 前端

- **player/core.js**：`destroyPlyr()` 现在对称清理所有 `applyPlyr()` 期间创建的资源引用，包括 `window.plyrPlayer`、`window.callPlyr`、`stallCheckTimer`（模块级保存）、`volumechange`/`ratechange` DOM 事件监听器。
- **player/audio-track.js**：`setupAudioTrackHandling()` 现在返回 cleanup 函数（通过导出的 `cleanupAudioTrackHandling()` 调用），清理每 3 秒运行的 `setInterval` 和 `loadedmetadata`/`change` 事件监听器。
- **player/play.js**：设置新 `openBtn.onclick` 前先 `revokeObjectURL` 旧的 Blob URL，防止每次播放带字幕的视频时泄漏一个 Blob URL。
- **api.js**：`apiGet`/`apiPost` 先检查响应 `Content-Type`，对非 `application/json` 的响应（如 Nginx 502 页面）抛出包含状态码和原始文本的错误，不再静默返回空对象 `{}`。
- **lyrics.js**：`renderLyrics()` 渲染时将节点数组缓存到 `state.lyrics.nodes`，`updateLyricsByTime()` 直接使用缓存，避免每次 `timeupdate` 都执行 `querySelectorAll`。
- **ui/bindings.js**：搜索框 `input` 事件增加 200ms debounce。
- **player/resume.js**：全局键盘热键保存 handler 引用，导出 `unbindGlobalHotkeys()` 用于对称清理。

### 后端

- **cache/media.go**：`buildAndUpdate` 签名从 `(resp, etag)` 改为 `(resp, etag, error)`。所有错误路径（`BuildMediaResponse` 失败、`json.Marshal` 失败）返回 error 并跳过缓存更新，调用方 `GetOrBuild` 和 `rebuild` 记录错误日志。避免空/无效响应被写入缓存导致用户看到空白媒体库。
- **service/logger.go**：`RotateLogIfNeeded` 关闭旧日志文件后，若重新打开失败，不再让 `log.SetOutput` 保持指向已关闭的文件描述符，而是回退到 `os.Stderr` 并记录错误。
- **handler/config.go**：定义 `ErrSharePathNotFound`、`ErrSharePathMissing`、`ErrUnsupportedOp` 三个 sentinel error。`HandleShares` 使用 `errors.Is()` 判断错误类型，替代之前脆弱的 `strings.Contains(err.Error(), "exists")` 字符串匹配。同时修正了 HTTP 状态码：输入验证错误从 500 改为 400。
- **handler/middleware.go**：
  - `getClientIP` 从 `strings.LastIndex(ip, ":")` 改为 `net.SplitHostPort`，正确解析 IPv6 地址（原逻辑会把 `[::1]:8099` 截断为 `[::1`）。
  - `statusWriter` 新增 `Unwrap() http.ResponseWriter` 方法，使 Go 1.20+ 的 `http.NewResponseController` 能正确透传底层 `ResponseWriter` 的 `Hijacker`、`ReaderFrom` 等可选接口。

### 测试

- **新增 `internal/handler/common_test.go`**：覆盖 `writeJSON`（正常写入 + marshal 错误回退）、`writeError`、`decodeJSONBody`（正常解码 + payload 过大 + 无效 JSON）、`isPayloadTooLarge`、`writeJSONDecodeError`。
- **新增 `internal/handler/stream_test.go`**：覆盖 `decidePlaybackMode`（12 种编解码器组合）、`checkTranscodePolicy`（6 种配置组合）、`resolveMediaTarget`（缺少 id、无效 id、不允许的文件）。
- **修复 `subtitle_test.go`**：补充缺失的 `newTestServerWithShare` 辅助函数，修复已有的编译错误。

## 验证

```bash
cd web && bun install && bun run build
go test ./...
go vet ./...
```

全部通过。

## 影响评估

- **前端**：播放器生命周期更健壮，长期运行后内存不再持续增长。API 错误处理更严格，调试非 JSON 响应（如代理错误页面）更容易。
- **后端**：缓存层不再缓存无效数据；日志轮转失败有明确降级策略；错误类型判断不再受错误文案修改影响；IPv6 环境（如现代 Docker 网络）的 IP 过滤正确工作。
