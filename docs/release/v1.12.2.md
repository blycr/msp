## v1.12.2

### 修复

- **桌面端展开播放列表时封面溢出封面区**：封面此前固定 200×200 且 `object-fit: cover`，而中间列在播放列表展开后变窄，封面于是被挤出槽位/被裁切。现封面放入 `audioCoverSlot` 槽内左右居中，宽度 `min(200px, 100%)`、`aspect-ratio: 1` 等比缩小，`object-fit: contain`；窄断点（≤1024px）恢复原固定尺寸，歌词布局不变

### 仓库卫生

- **行尾归一化**：新增 `.gitattributes`，仓库中 **170 个以 CRLF 提交的文本文件**统一为 LF（二进制资源如 `*.png`、`*.ttf`、`*.exe` 显式声明为 binary，不参与转换）
  - 此前 Windows 检出（`core.autocrlf=true`）与 Linux CI 检出的字节不同；`git diff`/`gofmt` 会因此产生整文件级别的假差异
  - `internal/handler/middleware.go` 是唯一以 CRLF 提交的 Go 文件，也是本次加入 `gofmt` 门禁后唯一会失败的源文件，现一并修正
- **清理行尾空白**：`internal/util/util.go` 两处

### 代码质量

新门禁暴露并修复的真实问题（不是为过 lint 而改）：

| 位置 | 问题 | 处理 |
|------|------|------|
| `internal/config/validate.go` | 三处 `fmt.Errorf("...: %v", err)` 丢失错误链，调用方无法 `errors.Is` | 改 `%w` |
| `internal/storage/sqlite.go` | 两处 `err == gorm.ErrRecordNotFound`，被包装的错误会漏判 → 进度/扫描元数据读取行为不一致 | 改 `errors.Is` |
| `internal/scanner/scanner.go` | `append(head, tail...)` 在 `head` 有余量时会写回其底层数组 | 改 `append(b, ...)` |
| `internal/util/util.go`、`internal/config/validate.go`、`internal/scanner/subtitle.go` | if-else 链改 switch（等价重构） | 已改 |

- **lint 门禁扩展**：新增 `errorlint`、`bodyclose`、`rowserrcheck`、`sqlclosecheck`、`nilerr`、`unconvert`、`wastedassign`、`gocritic`；启用 `gofmt` + `goimports` formatter
  - `gocritic` 仅保留默认检查集：开启整个 `style`/`performance` 标签会引入约 200 条 `hugeParam`/`rangeValCopy` 类微优化噪声，性价比为负，故不做
  - `exitAfterDefer` 显式豁免：`main()` 对不可恢复的启动错误有意使用 `log.Fatal*`
  - `internal/handler/config.go` 的 `appendAssign` 以 `//nolint` 标注保留：该处需要让 `next` 与 `cfg.Shares` 底层数组彼此独立，是刻意的 copy-on-write
- CONTRIBUTING 一直写着"严格强制 gofmt"，但 CI 从未检查；本次补上。

### CI / 依赖

- **前端不再在矩阵里编 8 次**：新增 `frontend` job 构建一次并上传 `web-dist` artifact；`test` 与 8 个目标的 `build-check` 改为下载该 artifact。8 个目标产出的是同一个前端包，重复构建纯属浪费
- **新增 `vulncheck` job**：`govulncheck ./...`，`continue-on-error: true` —— 结果只作告警，不让新披露的 CVE 或 vuln.go.dev 抖动阻塞发布
- **Bun 缓存 key** 由 `package.json` 改为 `bun.lock`（依赖键应指向锁文件）
- **`push` 触发去掉 `pull_request` 的重复**：同仓 PR 此前会跑两遍
- **Dependabot** 新增 `docker` 生态，覆盖 `Dockerfile` 的 `oven/bun`、`golang`、`alpine` 三个基础镜像

### 升级说明

无需迁移。`config.json` / `msp.db` / `msp.key` 格式未变。仓库级行尾归一化只影响开发者检出，不影响运行时行为。

如果你是开发者且已有本地修改：`git stash` → `git pull` → 视需要 `git config core.autocrlf false`（`.gitattributes` 已固定 `eol=lf`，新检出都是 LF）。
