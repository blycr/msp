## v1.13.0

本版修掉了**媒体探测链路上三个串联的缺陷**。它们不是新功能，而是让 v1.11.0 起就已宣传的两项能力（「按真实编码智能转码」「内嵌字幕」）实际没有生效。

### 你会在使用中直接感受到的变化

- **内嵌字幕终于出现了**：此前 MKV/MP4 内封的文本字幕轨一条都列不出来（字幕菜单里只有外挂 `.srt`/`.ass`），现在会正常列出并可选。
- **H.264 视频转码不再被重编码**：以前任何转码都会把视频整段重编（画质二次损失、CPU 高），现在只要视频是 H.264 就直接流拷贝，只转音频。
- **拖动更细、回退不再从头播**：HLS 分段由实际约 10 秒变为 4 秒；直连解码失败自动回退转码时，从当前播放位置继续，而不是回到 0:00。
- **AVI/TS/WMV/WebM 能识别编码了**：此前这些容器的编码信息恒为空，只能先直连失败再靠回退兜底。

### 根因

1. **探测命令整体失败**：`ffprobe -select_streams v:0,a:0,s` 是非法写法。`-select_streams` 只接受单个 stream specifier，逗号并列会让 ffprobe 报 `Invalid stream specifier` 并以**退出码 1** 结束，整次探测被放弃。于是 `GetCodecInfo` 永远返回错误，`/api/probe` 退化为「前 2MB + 后 2MB 的字节嗅探」，而嗅探只覆盖 `mkv/mp4/m4v/mov`。
2. **字幕索引语义错位**：`/api/probe` 下发的 `subtitle.id` 是 ffprobe 的**全局 stream index**，提取时却用了 `-map 0:s:<n>`（第 n 条字幕流的相对序号）。单字幕文件匹配不到任何流（404），多字幕文件会取到别的轨道。
3. **HLS 两个参数问题**：`-hls_time 4` 只是下限（实际按关键帧间隔切，约 10 秒）；`start` 参数完全没被使用（`buildHLSArgs` 没有引用 `opts.Offset`）。

### 顺带修掉的

- `-show_entries` 里用 `stream=language,title` 取标签是无效写法，改 `stream_tags=`；否则字幕的语言/标题永远是空的。
- 过滤 `attached_pic`：带封面的 `.m4a`/`.mp3` 第一个 video 流是封面图（mjpeg），不过滤会把纯音频判成需要转码。
- 字幕语言标签补 `chi`/`zho`（Matroska 里中文轨几乎都用 ISO 639-2 码）。
- `.gitignore` 的 `media/`、`data/`、`thumbs/` 没有锚定根目录，会匹配任意层级的同名目录 —— `internal/media/` 下的**新增文件会被静默忽略**。已改为 `/media/` 等，并补上 `msp.key`。
- CI：`check.yml` 的 `build-check` 在发布（`workflow_call`）时跳过，避免与 `release.yml` 自己的 8 目标矩阵重复，每次发布少跑 8 个构建任务。
- 文档漂移：Go 版本要求（三处仍写 1.25）、CodeMap 的技术栈与 Docker 镜像、已删除的 `internal/types` 包、SQLite 连接池描述、`API_REFERENCE` 的 `track` 语义与 HLS `start` 字段、`TRANSCODING` 的分段说明。

### 测试

新增 3 个需要真实媒体文件的集成测试（无 ffmpeg 环境自动跳过），以及 1 个不依赖 ffmpeg 的解析单测。存量 `TestParseProbeJSONWithSubtitles` 的 fixture 一并修正 —— 它原先断言的是 ffprobe 根本不会产出的 JSON 形状，属于「假绿」。

### 已知限制（本版未处理）

- **视频流拷贝时 HLS 分段仍等于源的关键帧间隔**（通常 10 秒）。这是 HLS 的机制约束：拷贝无法插入关键帧。要在这条路径也拿到 4 秒分段，只能改为重编码。
- **HLS 会话仍会占满转码槽**：服务端没有停止会话的接口，空闲 5 分钟才回收。默认并发为 2（软件转码）/ 4（硬件），因此连续切换 3 个需要转码的视频时，第 3 个可能报「转码失败」，等几分钟后自愈。
- 探测失败、`maxItems` 截断、符号链接共享根等其它已知问题不在本版范围内。

### 升级说明

配置、数据库与 API 均无破坏性变化，无需迁移。用 Docker 部署的用户直接拉新镜像即可。

唯一需要注意的是 `GET /api/stream?...&hls=1` 的响应**多了一个 `start` 字段**，并新增支持的 `start` 参数语义（HLS 起播位置）。旧客户端忽略新字段即可正常工作。
