# v1.2.0 Release Notes

## FFmpeg 多路径发现

FFmpeg/ffprobe 查找逻辑从单一 `PATH` 搜索升级为 7 层优先级搜索：

1. `MSP_FFMPEG_PATH` 环境变量
2. 可执行文件同目录
3. `bin/` 子目录
4. 当前工作目录
5. `CWD/bin/`
6. 平台特定路径（如 `/usr/local/bin`、`C:\ffmpeg\bin`）
7. 系统 `PATH`

查找结果通过 `sync.Once` 缓存，全程零重复开销。当 FFmpeg 不可用时，转码并发上限自动设为 0，启动日志明确显示 `"unavailable (FFmpeg not found)"` 而非误导性的 `"software (libx264)"`。

## 后端播放策略（方案 B）

`/api/probe` 响应新增 `playback.mode` 字段，由后端根据实际编码信息决策：

```json
{
  "container": "MKV",
  "video": "H.265/HEVC",
  "audio": "AC-3",
  "playback": { "mode": "transcode" }
}
```

决策逻辑 `decidePlaybackMode()` 覆盖主流编码：

| 视频编码 | 模式 |
|---------|------|
| H.264/AVC | direct |
| H.265/HEVC | transcode |
| AV1 | transcode |
| VC-1/WMV3 | transcode |

| 音频编码 | 模式 |
|---------|------|
| AAC/MP3/Opus/Vorbis/FLAC | direct |
| AC-3/DTS/TrueHD | transcode |

编码检测基于字节嗅探（`SniffContainerCodecs`）和 ffprobe，兼容 byte-sniff 标签（`"H.264/AVC"`）和 ffprobe 原始名（`"h264"`）。

## 前端播放策略集成（方案 B 前端）

新增 `getPlaybackUrl(item)` 异步函数，替代原有的前端后缀名猜测逻辑：

- 查询 `/api/probe` 获取 `playback.mode`
- `"transcode"` → 返回 `url + "&transcode=1"`
- `"direct"` → 返回原始 URL

消除了前端 `needsCompatibilityVideoTranscode()` 的扩展名猜测、`probeWarnText()` 警告文案、以及 5-10 秒的解码失败后回退延迟（现在约 50ms probe 耗时）。

## CSS 性能优化（方案 C）

- **`.panel` / `.now`**：移除不可见的 `backdrop-filter: blur()`（不透明背景遮挡了模糊效果）
- **`.topbar`**：模糊半径 12px → 8px，新增 `contain: layout style` + `will-change: transform` 启用 GPU 合成层
- **`.ly`（歌词非活跃行）**：`filter: blur(1.5px)` → `opacity: 0.4`，避免每帧触发 GPU 滤镜重绘
